# 실행 시 확인하고 사용자 승인 후 앱을 업데이트한다

2026-10-19 사용자와 설계 합의.

## 결정

앱 실행 시 GitHub Releases의 공개 릴리스를 확인한다. 프리릴리스를 포함하고, 현재보다 SemVer가 높은 버전 중 설치된 앱과 같은 CPU의 설치 파일·서명·매니페스트가 모두 있는 최신 버전을 제안한다. 운영체제가 ARM64여도 x64 앱이면 x64를 유지한다.

설치 사용자가 승인하면 다운로드와 검증을 마치고 앱을 종료한다. 별도 도우미가 앱 종료를 기다려 기존 경로에 설치한 뒤 앱을 재실행한다. 온보딩 작업 중에는 앱 업데이트를 시작할 수 없다. 미루기·조회 실패·다운로드 또는 검증 실패는 기존 앱 사용을 막지 않는다.

상주 서비스, 예약 작업, 강제 업데이트, 자동 다운그레이드는 도입하지 않는다.

## 신뢰 경계

앱에 RSA 공개키를 내장한다. 릴리스 작업은 별도 개인키로 버전·CPU·파일명·SHA-256을 담은 매니페스트 원문을 RSA-3072/SHA-256/PKCS#1 v1.5로 서명한다. 앱은 전자서명과 메타데이터 및 설치 파일 해시를 검증하고, 도우미가 실행 직전 다시 검증한다. 서명 누락·검증 실패 시 실행하지 않는다.

HTTPS와 같은 릴리스에 올린 해시만 사용하는 방식은 저장소 배포물 변조 시 신뢰 기준이 함께 바뀌므로 채택하지 않았다. Windows Authenticode와 이 업데이트 전용 서명은 별개다. 이 서명은 SmartScreen·Defender 경고를 해제하지 않는다.

## 결과와 한계

키 교체는 기존 앱이 새 공개키를 신뢰할 수 있도록 이전 키로 배포하는 전환 릴리스가 필요하다. 이전 개인키를 잃으면 수동 재설치가 필요할 수 있다. 서명된 과거 버전의 재전송은 현재 버전 이하이면 거부하지만, 최신 릴리스의 존재 자체를 숨기는 공격까지 탐지하지는 않는다.

기존 NSIS 설치를 재사용하므로 설치 실패 시 자동 롤백은 없다. 설치 중 디스크 오류 등으로 부분 교체되면 수동 재설치가 필요할 수 있다. 동일 사용자 권한의 악성 프로세스와 관리자에 의한 로컬 변조는 기존 앱과 같은 보호 범위 밖이다. 업데이트는 앱 파일을 교체하며 Tailscale 연결과 SSH 설정을 변경하지 않는다.
