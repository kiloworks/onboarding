# 앱 업데이트 운영

앱 실행 시 새 버전을 확인하고 ‘업데이트’, ‘나중에’, ‘릴리스 설명’을 제공한다. 프리릴리스도 대상이다. 작업 중 업데이트는 제공하지 않는다. 조회 실패나 설치 전 검증 실패는 기존 버전 사용을 막지 않는다. 승인 후 다운로드·검증을 마치면 앱을 종료하고 같은 경로에 설치한 뒤 다시 실행한다.

## 배포

기존 태그 배포 작업이 설치 파일마다 `.manifest.json`과 바이너리 `.sig`를 추가한다. `config/update-public-key.xml`에 대응하는 RSA XML 개인키를 GitHub Actions secret `ONBOARDING_UPDATE_PRIVATE_KEY`에 설정해야 한다. 키 누락 또는 공개키 불일치 시 릴리스 작업은 실패하며 서명 없이 배포하지 않는다. 개인키는 로그·저장소·아티팩트에 넣지 않는다.

최초 설정한 개인키의 로컬 보관 위치는 `~/.local/share/kiloworks-onboarding/update-signing-private.xml`이며 권한은 0600이다. 접근을 제한하고 별도 안전한 백업을 보관한다. Actions secret은 읽어서 복구할 수 없다. 키를 교체할 때는 [설계 결정](adr/0007-approved-app-updates.md)의 전환 제약을 따른다.

이 기능이 없는 기존 배포본은 자동으로 기능을 얻지 못한다. 첫 도입 버전은 수동 설치해야 한다. 현재 버전보다 높은 Cargo 버전과 일치하는 `v<버전>` 태그를 발행한다. NSIS의 설치 파일명과 DisplayVersion도 Cargo 버전과 맞춰야 한다. 릴리스 설명은 앱에서 GitHub 페이지로 연다.

앱은 공개 GitHub API를 인증 없이 호출한다. 오프라인·API 제한 시 다음 실행에서 다시 확인한다. 다운로드 임시 파일은 성공 또는 일반 오류 시 정리되며, 강제 종료·전원 차단 시 OS 임시 폴더에 남을 수 있다. 설치 도우미 실패는 Windows 메시지로 알린다. 기존 설치 프로그램은 자동 롤백을 제공하지 않으므로 부분 설치 실패 시 공식 설치 파일로 재설치한다.

## 검증

`cargo test --locked`는 버전 선택·CPU 유지·프리릴리스 순서·구버전 거부·서명 파일 누락을 검사한다. `scripts/check-updates.ps1`는 테스트 전용 키로 실제 서명과 검증을 수행하고 파일·매니페스트 변조와 버전·CPU 불일치를 거부하는지 확인한다. CI는 PowerShell 7과 Windows PowerShell 5.1에서 이 검사를 실행한다.

Windows CI는 실제 설치 파일을 테스트 키로 서명하고 다운로드 전송만 로컬 파일로 대체하여 앱 종료 대기 → 기존 경로 교체 → 네이티브 창 재실행 → 사용자 파일 보존을 검사한다. 실제 공개 릴리스의 조회·다운로드와 사용자 승인 UI를 포함하는 전체 경로, 실제 Windows 10/11 클라이언트 실기 검증은 별도다.
